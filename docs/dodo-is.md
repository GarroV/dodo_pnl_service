# Dodo IS: с чего продолжать

> Входная точка по теме коннектора. Отвечает на четыре вопроса — что решено, что
> уже сделано, что делать дальше и чего мы до сих пор не знаем. Подробностей
> здесь нет намеренно: каждая живёт в одном месте, сюда собраны только ссылки и
> состояние. Заведено 31.08.2026, когда разбор закончился, а работа — ещё нет.

## Что решено

Три решения владельца, принятые 30–31.08.2026. Они сужают задачу настолько,
что половина разбора API оказалась справочной, а не рабочей.

| | Решение | Где записано |
|---|---|---|
| **D061** | Зарплату из Dodo IS не берём ни в каком виде — ни начисления, ни премии, ни сверку | [decisions.md](forge/decisions.md) |
| **D062** | Берём **только отработанные часы**. Ни выручки, ни себестоимости, ни метрик. Отменяет прежний порядок D044 «часы → сырьё → выручка» | [decisions.md](forge/decisions.md) |
| **D063** | Коннекторы включаются по одному и по умолчанию выключены; есть режим сверки, который не влияет на итоги | [decisions.md](forge/decisions.md) |

Причина D061 и D062 одна и стоит того, чтобы её помнить: **продукт строится,
чтобы считать оклады и коэффициенты самому.** Всё, что Dodo IS уже посчитал, не
нужно по определению — второй источник истины обесценивает движок, а при
расхождении непонятно, какая цифра правильная. Часы — единственное, чего у нас
нет и что вбивают руками каждый месяц.

Слова владельца, чтобы не пересказывать: «ОТ ДОДО ИС НУЖНЫ ТОЛЬКО ЧАСЫ».

## Что уже сделано

**Разбор API закончен.** Спека вычитана машинно, не глазами: сайт документации —
SPA, но её данные лежат в открытом API Stoplight. Отсюда точные пути, scope,
параметры и **поля ответов** — последнего не было в коллекции Postman, и именно
поэтому прежний разбор ошибся дважды.

| Что | Где |
|---|---|
| Разбор API: доступ, авторизация, scope, что берём и почему | [dodo-is-api.md](dodo-is-api.md) |
| Машинный каталог: 109 методов четырёх проектов с полями ответов | `docs/dodo-is-catalog.json` |
| Инструмент: пересобрать каталог, сверить, поискать по полям | `tools/dodo_is_catalog.py` |
| Пошаговый гайд подключения (восемь шагов, чек-листы) | `docs/guides/dodo-is-connect.html` + [реестр материалов](user-guides.md) |

Каталог не читается целиком — по нему ищут:

```bash
python tools/dodo_is_catalog.py --grep расстояние   # где лежит километраж
python tools/dodo_is_catalog.py --check             # не разошлась ли документация
python tools/dodo_is_catalog.py                     # пересобрать
```

**Механизм включения готов и лежит в продукте** (D063). У каждого потока данных
три состояния, а не флаг: `off` — не тянем, `trial` — тянем и показываем рядом,
но **в расчёт и в P&L не берём**, `on` — берём в работу.

| Что | Где |
|---|---|
| Таблица, enum, политики доступа | `src/core/migrations/0260_data_feeds.py` |
| Правило «идёт ли это в расчёт» — единственное место | `src/core/feeds.py` |
| Применение: часы невзятого источника останавливают расчёт | `src/payrun/calc.py`, `collect_cases` |
| Проверки, включая изоляцию ролью `app_user` | `tests/test_data_feeds.py` |

Часы из невзятого источника **не пропускаются молча**: расчёт останавливается и
называет людей. Недосчитанная ведомость выглядит точно так же, как правильная, —
и это худшее, что могло бы случиться.

## Что делать дальше

Порядок и подробности — в гайде `docs/guides/dodo-is-connect.html`. Здесь только
рамка, чтобы понять, где мы стоим.

**Шаги 1–4 организационные и делает их владелец.** Пока они не пройдены, код не
пишется: коннектор к API, ответа которого никто не видел, — гадание.

1. Собрать три вещи: почта, учётка партнёра с ролью не ниже `Store Manager`, и
   договорённость, **под чьей учёткой коннектор ходит постоянно**.
2. Завести приложение в кабинете разработчика, поток — Device Flow.
3. Взять первый токен руками и посмотреть, пришёл ли `refresh_token`.
4. Достать настоящие часы за настоящий месяц.

Задача заведена: **issue #132**, в графе — **T175**.

**Шаги 5–8 — код**, и они начнутся после четвёртого: хранение и обновление
токенов, сопоставление точек и людей, сам забор, включение через месяц сверки.

Одна развилка, которую в шаге 6 придётся решить владельцу: часы приходят с
`staffId`, а не с фамилией. Либо привязать людей руками один раз, либо тянуть
`/staff/members` — но тогда в базу приезжают ФИО, телефоны и налоговые номера
живых людей, а репозиторий публичный. Рекомендация — руками.

## Чего мы не знаем

Всё, что записано про адреса, scope и поля, снято из спеки и проверяемо
командой. Эти три вещи спека не говорит — они выясняются первым живым вызовом:

- **Даёт ли Device Flow обновляемый токен.** Единственное, что способно
  изменить план: без `refresh_token` фоновый забор невозможен, и тогда нужен
  Authorization Code — а это второе приложение (Client Id привязан к потоку) и
  постоянный адрес возврата.
- **Лимиты по частоте запросов.** В спеке нет ни заголовков лимита, ни ответа
  `429`. Первая же выкачка истории покажет.
- **Глубина истории.** Ни один метод не объявляет предела периода.

Четвёртое, помельче: на страницах методов висит «доступ к API выдаётся после
публикации приложения в маркетплейсе и модерации». Разбор говорит, что публикация
— про распространение приложения другим франчайзи, а не про доступ для себя
(D043). Логика сходится, фактом подтвердится на четвёртом шаге.

## Что стоит помнить, когда вернёмся

**База API у Сербии — `https://api.dodois.com/dodopizza/rs`.** Домен `.com`, а не
`.io`: все примеры документации показывают Россию. И база зависит не только от
страны, но и от сервиса — роли живут на `…/auth`, ревизии на
`…/dodopizza/inventory`. Коннектор на одном шаблоне пути до половины не
достучится.

**Смена приезжает уже разложенной** на дневные, ночные и праздничные минуты, с
должностью на смене, стажем и метражом поездок курьера. Считать это самим не
надо — но границу месяца резать придётся по `dailyStatistics`: смена
возвращается целиком, если в период попало её начало.

**Часы правятся задним числом** (`lastModifiedAt`, история изменений). Значит
закрытый период может поехать уже после расчёта. Что с этим делать —
пересчитывать, показывать расхождение или игнорировать — решения пока нет, и его
надо будет принять.

**Соблазн взять больше будет возвращаться.** API отдаёт готовую зарплату по
сменам, выручку одним дешёвым scope, себестоимость. Каждый раз ответ один и тот
же: D062. Механизм D063 существует для того, чтобы расширение объёма было
настройкой и месяцем сверки, а не переписыванием.
