# Блок: deploy

## Назначение

Продукт, поднятый там, где им можно пользоваться, и проверки, не дающие сломать его
незаметно. Выделен отдельно, потому что площадка накладывает свои ограничения:
домашний Windows-сервер с чужими соседями по портам и по Docker.

## API-контракт

Наружу отдаёт запущенный продукт и набор переменных окружения (имена, не значения):

| Переменная | Смысл |
|---|---|
| `DATABASE_URL` | подключение к боевой базе |
| `DEMO_DATABASE_URL` | подключение к демо-базе |
| `APP_PORT` | порт приложения — 8030 на сервере, 8000 локально |
| `POSTGRES_HOST_PORT` | порт базы наружу — 5440, только на localhost |
| `SECRET_KEY` | ключ подписи сессий Django |
| `DJANGO_SETTINGS_MODULE` | окружение настроек |
| `PAYROLL_FIXTURE` | локальный путь к эталонной таблице; только у владельца, в репозиторий не попадает |

Ограничения площадки, которые нельзя нарушать:

- **свой compose-проект** из `C:\projects\_template`, свой Postgres-контейнер;
  существующий стек `supabase-*` принадлежит staging Swarm Brain и не трогается;
- заняты и не используются: 8020, 8043, 5433, 6543, 5678, плюс порты БД ботов;
- контейнер базы помечается `backup.pgdump=true`, чтобы попасть в существующую
  задачу резервного копирования сервера;
- GUI и долгие процессы не запускаются напрямую из ssh — только через задачу
  планировщика, иначе процесс убивается вместе с сессией.

## Зависимости

Блоки: `db` (миграции применяются при развёртывании), `web` (что именно поднимаем).

Внешнее: Docker Compose на MUSPELHEIM, GitHub Actions для проверок на pull request.

## Definition of Done блока

- [ ] `docker compose up -d --build` поднимает продукт локально с нуля по README
- [ ] `.env.example` полон: с ним проект поднимается, без секретов внутри
- [ ] Продукт поднят на MUSPELHEIM, отвечает по адресу сервера на порту 8030
- [ ] Смоук на сервере, а не локально: вход, ввод часов, расчёт, ведомость
- [ ] Проверка доступности падает, когда продукт лежит — проверено остановкой
      контейнера, а не предположением
- [ ] Контейнер базы попадает в ночную задачу резервного копирования — проверено
      наличием свежего дампа
- [ ] CI на каждый pull request: линт, тесты, сборка образа
- [ ] Соседние проекты на сервере продолжают работать — проверено списком
      контейнеров до и после

Переменные окружения, которые реально читает код (сверено грепом по `src`,
`tests`, `manage.py`, а не по памяти): `SECRET_KEY`, `DJANGO_DEBUG`,
`DJANGO_ALLOWED_HOSTS`, `DATABASE_URL`, `DJANGO_SETTINGS_MODULE`,
`PAYROLL_FIXTURE`, `DODO_TEST_ADMIN_DSN`. Из них в `.env.example` не хватало
`DJANGO_DEBUG` и `DJANGO_ALLOWED_HOSTS`, а `DATABASE_URL` расходился по паролю
с `POSTGRES_PASSWORD` — то есть скопировать пример и получить рабочее окружение
было нельзя. `DEMO_DATABASE_URL` в коде пока не читает никто: он из контракта,
за ним придёт блок `demo`.
