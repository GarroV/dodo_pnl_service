# Компоненты интерфейса

Из чего собираются экраны. Правило одно: **разметку, у которой есть компонент,
руками не пишут.** Не ради краткости — в этих компонентах живут решения,
купленные дефектами, и своя копия такого решения через месяц разъезжается тихо.

Файл описывает нынешний состав. Расходится с кодом — прав код, а файл надо
чинить тем же изменением.

## Теги (`{% load ui %}`)

| Компонент | Что даёт | Почему он один на продукт |
|---|---|---|
| `{% notice "ok\|alert\|empty" title="…" extra="…" %}…{% endnotice %}` | плашка: получилось / помешало / пусто | Три вида и никаких других: четвёртый заводится, только если можно объяснить, чем он отличается. `empty` — пустое состояние, место будущего онбординга (T077) |
| `{% scroll %}<table …>{% endscroll %}` | контейнер широкой таблицы | Прокручивается контейнер, а не страница. Требование «ведомость читается на 1440» меряется у **контейнера**: страница не едет никогда, и первый смоук был зелёным при 191px перелива |
| `{% ledger row.ledger %}` | метка регистра учёта | Метка, а не заливка строки (D023). Показывает **название, уже отобранное для роли** — в справочник регистров не ходит, иначе однажды назовёт чужой регистр |

Текст плашки пишется **телом тега**, а не приезжает параметром из Python:
локализация (T017) переводит строки шаблонов, а строку, собранную в
представлении, ей не достать.

## Включения (`{% include %}`)

| Компонент | Что даёт | Почему он один на продукт |
|---|---|---|
| `components/action.html` | действие — или объяснение, почему его нет | T072: кнопка не смеет пропасть молча, иначе запрет читается как поломка продукта. Текст отказа берётся тот же, которым ответит сам отказ (`permissions.explain`) |
| `components/cuts.html` | переключатель разреза | Список собирается из показанных данных, а не из справочника (D023): пустая кнопка с названием регистра — тоже сообщение о том, что он есть. Выбранный разрез — не ссылка |
| `components/field.html` | поле формы: подпись и ввод | Подпись связана с полем через `id`, иначе поле недоступно с клавиатуры и диктору |
| `components/diff_table.html` | таблица «в таблице — в расчёте — разница» | Один вид данных на экране сверки показывается дважды (существенное и копейки) |
| `components/header.html` | шапка: навигация, роль, регистры, точка | Раздел 08 дизайн-системы (T178). Роль — **одна** плашка: решение владельца, у человека один уровень; в эталоне рядом нарисованы все выданные наборы (issue #130). Точка называется только там, где человек ею ограничен |
| `components/appnav_item.html` | пункт навигации: ссылка — или не ссылка, если человек уже здесь | Текущий раздел — `span[aria-current="page"]`, тот же инвариант, что у `cuts.html`. «Уже здесь» считается по корню адреса (`in_section`), иначе выделение пропадает на каждом вложенном экране — на следе расчёта, в табеле, на карточке платежа |
| `components/htmx.html` | подключение htmx | Единственное место, где названы версия и путь (D017). Подключается осознанно, экрану без `hx-*` htmx не нужен |

### Действие с обязательной причиной вместо диалога подтверждения

Отдельного модального диалога в продукте нет намеренно. Подтверждение нажатием
(«вы уверены?») не сохраняет ничего: через полгода никто не вспомнит, зачем
период открывали. Поэтому опасное действие подтверждается **причиной** —
`reason_*` у `action.html`, — и она уходит в историю рядом с именем
(D021, конституция об обратимости). Диалог вернётся, когда появится действие,
которое нельзя откатить вовсе; сейчас такого нет.

## Числа

Соглашение блока, обязательное для всех экранов: деньги и часы — `class="num"`
(правый край, моноширинное начертание, `tabular-nums`), главное число строки —
`class="num strong"`. Пустое значение — прочерк, а не ноль: за это отвечает
`web/format.py`, и обходить его подстановкой нуля в шаблоне нельзя.

## Оформление

Два файла статики, подключаются в `base.html` в этом порядке:

| Файл | Что внутри | Кто его правит |
|---|---|---|
| `static/web/tokens.css` | значения дизайн-системы: цвет с семантикой, типографика, плотность строк, радиусы, тени, длительности; второй набор значений для тёмной темы; локальные `@font-face` | копия эталона «Дизайн-система Dodo P&L» — правится только вместе с ним |
| `static/web/app.css` | правила на этих значениях: каркас, шапка, кнопки, поля, таблицы, плашки, полоса шагов | наш, меняется вместе с экранами |

Правила листа три, и все три проверяются `tests/test_visual_tokens.py`:

1. **Ни одного литерального цвета** нигде, кроме `tokens.css`. Литерал в
   шаблоне или во втором листе — это вторая палитра, то есть ровно то
   «вразнобой», из-за которого продукт нельзя было показать владельцу.
2. **Геометрия и типографика — из дизайн-системы**: `--space-*`, `--r-*`,
   `--fs-*`, `--row*`. Своё число заводится, только если объяснено, почему ни
   одно готовое не подошло.
3. **Классы остаются продуктовыми.** Экраны переезжают на систему по одному,
   по правилу владельца: «экран, которого касаемся по любой задаче, переезжает
   тем же изменением».

До T177 лист лежал внутри `<style>` в `base.html`, и это была не лень:
`runserver` при `DJANGO_DEBUG=0` статику не отдаёт вовсе. Причина ушла —
статику отдаёт whitenoise (issue #68), и `tests/test_static_files.py` проверяет
это запросом файла при `DEBUG=False`, а не «по коду».
