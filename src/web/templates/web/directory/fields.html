{% comment %} Поля формы справочника: список приезжает из представления. Почему цикл, а не поля россыпью в каждом шаблоне. Состав полей у пяти справочников разный, а правила показа — одни: подпись связана с вводом через `id` (`components/field.html`), выбор из справочника — списком (`components/select.html`), у необязательного выбора есть подписанный пустой вариант. Написанные пять раз, эти правила разошлись бы, и поле без подписи появилось бы там, где его никто не проверяет. `id` поля собирается из его имени (`id_`), а не приходит отдельным значением: два источника одного `id` — верный способ развязать подпись и ввод молча. Виды: text, number, date, month, select, checks, file, note. Незнакомый вид рисуется обычным полем — это осознанно: молча пропущенное поле человек не заметит, а лишнее текстовое увидит сразу. `file` — выбор файла (фотография бумаги с точки, T174). Форма с таким полем обязана быть `enctype="multipart/form-data"`, иначе браузер пришлёт одно имя файла вместо его содержимого, и продукт честно откажет «файл не приложен». `note` — значение без ввода: так показывается то, что человек вправе видеть, но не вправе менять (способ работы группы без права `rules.manage`). Не `readonly`-поле: поле, которое не принимает ввод, всё равно приглашает в себя щёлкнуть и печатать — то же решение, что в ячейках закрытой точки в табеле.
