Две таблицы, а не одна, потому что это два разных вопроса. «Что позволяет роль» меняют редко и всем сразу; «кто ею наделён» — по человеку. Смешанные в одну сетку, они дали бы экран, где галочка напротив имени означает то же, что галочка напротив роли, — а это разные вещи. Права показываются названиями действий, а не кодами: `payrun.calculate` — слова для разработчика. Названия берутся оттуда же, откуда их берёт отказ (`web/permissions.py`), чтобы человек прочитал на экране ролей ровно то, что прочитает в отказе, если права не окажется. Форма на роль своя — сохранение построчное. Одна форма на всю таблицу означала бы, что правка одной роли переписывает заодно и остальные: незаметно и молча. {% endcomment %} {% block title %}{% translate "Роли и права" %}{% endblock %} {% block content %}

{% translate "У кого какая роль" %}

{% comment %} Кого в этом списке нет и почему (T160). Пустого состояния у обеих таблиц здесь нет намеренно, и это не пропуск: экран открывается только по праву `roles.manage`, которое человек получает членством с ролью, — значит у смотрящего уже есть и роль, и членство, и таблицы при нём пусты быть не могут. А вот НЕполными они бывают, и это как раз тот случай, который пустое состояние обязано различать: список собирается из выданных ролей (`_people`, соединение с `roles` внутреннее), поэтому человек, у которого ролей нет, в нём не появляется вовсе. Молча это читается как «такого человека в системе нет» — то есть ровно как «не загрузилось», хотя данные на месте. Поэтому сказано словами. {% endcomment %}
