{% extends "web/base.html" %}{% load ui i18n %} {% comment %} Инбокс классификации (T152). Экран отвечает на один вопрос: сколько денег ещё не разложено по статьям и какие это траты. Сумма стоит сверху и приезжает готовой из представления — считать её в шаблоне нельзя, а вторая выборка разошлась бы с таблицей молча. Разбор идёт **в самом списке**: у каждой строки свои поля статьи и точки и своя кнопка. Отдельная страница на строку означала бы вдвое больше нажатий, чем самой работы: строки разбирают подряд, десятками. Строчная форма — на одну строку, а над таблицей стоит вторая, на пачку (issue #173). Они не дублируют друг друга: строчная разбирает свою строку со своей точкой, пакетная присваивает одну статью всем отмеченным. Чекбоксы стоят в ячейках, а форма — снаружи таблицы: формы в HTML не вкладываются, поэтому чекбоксы связаны с ней атрибутом `form`, а не положением в разметке. **Подсказка не разбирает за человека.** Если по этому поставщику решение уже принимали, статья предложена — отмечена в списке и названа в колонке «Похоже на». Строка при этом остаётся в инбоксе, пока человек не нажал «Разобрать»: молча назначенная статья уезжает в P&L и находится на сверке. **Второй список — бумаги с точек** (T174), и он отделён от первого нарочно. Разница между ними не в оформлении, а в деньгах: строка без статьи **уже** в P&L, только не в той статье, а бумага в P&L не входит вовсе — у неё ещё нет ни одной строки учёта. Один список с общим итогом сложил бы эти два числа, и получилась бы сумма, которой нет ни в одном отчёте. {% endcomment %} {% block title %}{% translate "Инбокс" %}{% endblock %} {% block content %}
